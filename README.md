## Overview

MOFDAEL couples a Python re-simulation of a 161 kV / 120 km transmission-line study (Z₁ = 0.080 + j0.390 Ω/km, Z₀ = 0.228 + j1.352 Ω/km) with eight machine-learning architectures and a numerical distance-relay baseline, then benchmarks all nine methods across five pre-registered evaluation criteria:

* **H₁ — Detection Accuracy**: overall binary fault detection vs the relay baseline (McNemar, Cochran's Q).
* **H₂ — Per-Phase Classification**: multi-label accuracy across phases A, B, C and Ground (per-target Cochran's Q + Holm).
* **H₃ — Reporting Latency**: per-row inference time vs the relay's 10 ms reference (Wilcoxon, Hodges–Lehmann).
* **H₄ — Robustness (TOST)**: accuracy stability under 1–20% injected noise, against a pre-declared 5 pp equivalence margin.
* **H₅ — Fault Location**: location error in km and as % of line length (Friedman + Holm-adjusted Wilcoxon).

*N.B: The datasets and every derived number in this repository were **regenerated on 2026-11-12** from the corrected simulation. In documents or notebooks where references are made to the superseded original datasets (14,400 rows, 45.8% fault rows, relay accuracy ≈ 0.9+, a 270 ms LSTM latency gap), treat those as legacy references — they no longer describe anything in this repository.*

## The Approach

### Physics first, models second

The fault scenarios are not scraped from a simulator GUI — they are generated by a transparent, code-only power-system model: a source behind an X/R = 10 impedance, a corrected 161 kV line with charging capacitance, and a constant-impedance load bus, solved per fault in the sequence domain and sampled at 1 kHz. The generator ships with an **8-point verification battery** that checks the physics against hand-computed cases before a single model touches the data.

### The relay is a real competitor, not a prop

The baseline is a numerical distance relay that decides on six loop impedances (three residual-compensated ground loops and three phase-phase loops) evaluated as steady-state phasors, with a Zone 1 reach of 0.80 × |Z₁| × 120 km = 38.22 Ω. Its profile on the regenerated data is **secure but incomplete**: it never trips on a healthy line (TN 100%) but catches only 49.2% of fault rows — precisely the gap the learned models fill.

### Reuse as a contract

The relay, the statistics, and the figure generator all import the same verified physics engine rather than re-deriving it:

```python
"""Reuse the verified physics engine — no re-derivation anywhere."""

from simulate import prefault_state, solve_fault, loop_impedances
from relay import zone1_reach_ohms

pre   = prefault_state(0.75)                      # 75% of 750 A load
fault = solve_fault("AG", 25.0, 60, 0.75, pre)    # AG fault, R_f = 25 Ω, 60 km
z_ga  = loop_impedances(fault["v_r_abc"], fault["i_r_abc"])[0]

print(z_ga < zone1_reach_ohms())                  # inside Zone 1 (38.22 Ω)?
```

Every script follows the same discipline: a timestamped `report_<timestamp>.txt` written to `outputs/<stage>/` alongside every CSV, and hard **verification anchors** asserted at load time — the pipeline refuses to build on a mismatch.

## The Data

| Dataset | Rows | Contents |
|:---|:---|:---|
| `data/classdetectfault_sim.csv` | 5,365 | Per-sample phasor samples (Ia…Ic, Va…Vc), fault location, and 4 phase targets (G, C, B, A) — 3,000 fault rows across 375 eight-row location sweeps + 2,365 no-fault rows |
| `data/detectfault_sim.csv` | 9,503 | Detection-only variant — 31.6% fault rows |

The design space spans 5 fault signatures × 5 fault resistances × 5 inception angles × 3 load levels × 8 fault locations. A scenario-level split assigns 134 of 671 scenarios (1,069 rows) to the shared test partition of all eight models, so every method is scored on identical rows.

### Quick Start

1. Regenerate the physics and datasets:
   ```bash
   .venv/bin/python src/simulate.py
   ```
2. Run the models and the relay baseline (`src/<model>.py` for each)
3. Run the statistical cascade:
   ```bash
   .venv/bin/python src/hypothesis.py
   ```
4. Generate the report and figures:
   ```bash
   .venv/bin/python src/analytics.py
   ```

Each stage prints its report to stdout **and** files a timestamped copy under `outputs/`.

## Conventions

- Every script follows the same skeleton: path configuration block → `ReportLogger` (stdout + timestamped report file) → `main()` guard
- Predictions are named `predictions_<model>.csv` so `src/hypothesis.py` discovers them automatically via glob
- All timestamps use `%Y-%m-%d_%H-%M-%S`; metrics print with `:.6f`; counts print as integers
- **Traceability rule:** every number is traceable to a line of code that can be re-run on demand
